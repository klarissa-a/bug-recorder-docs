# Что записывается

## Network в QA Lis

Во время записи QA Lis собирает доступные fetch/XHR-запросы основной страницы и поддерживаемых iframe связанных вкладок. В отчёте диагностика переключается между **Network** и [**Console**](./console.md).

Запрос может появиться сразу со статусом **В процессе**. После завершения та же строка обновляется до HTTP-статуса или **ERR**. Это не полный журнал всех соединений браузера: отсутствие строки не доказывает отсутствие сетевой активности.

## Данные запроса

В зависимости от доступности можно увидеть URL, метод, домен, HTTP-статус, длительность, связанный шаг, Headers, Payload и Response. Для GraphQL может показываться имя операции.

Распознанные ошибки включают не только HTTP 4xx/5xx: ответ HTTP 200 с прикладной ошибкой, например `result: false`, тоже может попасть в **Ошибки**.

Большие тела могут сокращаться, некоторые данные недоступны. Распознанные секреты маскируются. JSON подсвечивается, но содержимое остаётся текстом; копирование не добавляет оформление.

## Лимит каждой записи

Хранятся **последние 120 запросов** каждого бага или тест-кейса, включая служебные. После достижения лимита новый запрос заменяет самый ранний. Запись не останавливается.

Счётчик **N / 120** в панели относится к выбранной записи. Фильтры отчёта не уменьшают этот счётчик: они меняют только показанный список. Следующий баг или тест-кейс начинает с **0 / 120**.

## Служебные запросы

Распознанные запросы аналитики, рекламы и статистики по умолчанию скрыты из списка, но не удалены. Их можно показать. Распознанные ошибки не скрываются этим правилом.
