# Ожидаемый и фактический результат

## Ожидаемый результат

Опишите, что должно произойти по требованиям. QA Lis не придумывает требования за вас.

**Пример:** настройки сохраняются; после обновления страницы уведомления остаются выключенными.

## Фактический результат

Укажите наблюдаемый ответ системы. QA Lis может подставить последнее подходящее уведомление, ошибку формы или связанную ошибку Network. Ошибки могут приходить и из поддерживаемых встроенных форм.

**Пример:** после сохранения появляется сообщение «Не удалось сохранить настройки. Попробуйте ещё раз».

Если достоверного наблюдения нет, поле остаётся пустым. Отсутствие записанного изменения не доказывает отсутствие реакции сайта. Проверяйте автоматическую формулировку; ручная правка и очистка сохраняются.

## Длина и копирование

Каждое поле принимает до **800 символов**; рядом с подписью отображается **N/800**. При вводе и вставке текст ограничивается этим пределом.

ОР и ФР необязательны для копирования: пустые поля не блокируют кнопку и не требуют подтверждения. Их можно дописать после вставки, но для понятного баг-репорта лучше уточнить оба результата.

В [тест-кейсе](./test-case.md) фактического результата нет. Ожидаемый результат и необязательное постусловие имеют тот же лимит 800 символов.
